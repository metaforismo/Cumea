# Cumea v0.2.0 — Developer Preview Candidate

> Candidate notes. This version has not been tagged or published.

Cumea v0.2.0 turns the source-only baseline into a more practical daily workspace: agents can be
temporary, their deliverables open directly from chat, and native dictation is available in the
mobile composer. The release keeps the user-owned host, credentials, and model boundary intact.

## Highlights

- Permanent agents plus safely expiring 24-hour Quick bots that can be kept at any time.
- Queue another handoff behind a busy named agent, cancel it before dispatch, or start an explicit
  fresh task context after the current queue drains without duplicating the agent.
- Edit a prior user message to create a durable sibling branch, rerun from the surviving history,
  and move between versions from desktop or a paired phone without destroying the original turn.
- Clickable agent deliverables with bounded integrated Markdown, PDF, and semantic DOCX viewers.
- File drops and long pasted logs/code flow through the audited attachment pipeline instead of
  burying the composer or exposing arbitrary host paths.
- Native iOS/Android message dictation with editable partial results and foreground-only capture.
- Batched streaming and event persistence with paged, anchored mobile history and a jump-to-latest
  affordance, without introducing an additional virtualization dependency.
- Local configurable ACP subscription profiles, so different bots can use different ACP-compatible
  CLIs/models while sharing Cumea's `list_bots` and `ask_bot` collaboration tools.
- Refined system typography, neutral message surfaces, date separators, and isolated paint-batched
  desktop streaming based on measured interaction tokens rather than copied proprietary assets.
- System light/dark mobile presentation, an agent-list-first home matching native hierarchy, and a
  compact “Up next” queue instead of another command-center screen.
- Per-agent desktop text drafts that survive agent switches and restarts without changing the
  audited upload lifecycle for unsent attachments.
- A source-first landing page that explains the self-hosted ownership model without advertising an
  unsigned download.
- The existing provider adapters, secure mobile pairing, Mote avatars, approvals, routines, and
  user-provided local or cloud computer surfaces from v0.1.0.
- A shared provider-process layer for Windows CLI shims, process-tree termination, authenticated
  permission named pipes, and native title-bar controls. Windows remains source/CI-validated only
  until the hands-on package checklist is completed.

## Security and release inventory

- File paths resolve only inside an agent's allowed workspace and produce a short-lived,
  same-origin capability rather than a raw filesystem URL.
- Preview snapshots are size-bounded; DOCX handling rejects unsafe ZIP structure, excessive output,
  bad CRC data, and active content.
- Quick bots cannot expire while work, approvals, provider requests, or routines remain active.
- The CycloneDX inventory includes the production dependency graph, pinned CUA Driver executable,
  and the exact resolved Electron framework version used to package the desktop application.

## Preview boundaries

This remains a Developer Preview, not a production-support release. Local macOS packaging and
simulator/native compilation do not establish Developer ID signing, notarization, Gatekeeper,
physical-device microphone behavior, accessibility acceptance, or store readiness. Linux and
Windows still require hands-on package tests. Mobile dictation requires a development or
distribution build because Expo Go does not include the native speech module.

Laptop-off execution still requires Cumea to run on an authenticated machine or VM controlled by
the user. Cumea does not provide a managed cloud computer. Remote access must sit behind
user-controlled HTTPS or a private tunnel; the raw HTTP listener is not an internet-facing server.
