# Cumea v0.1.0 — Developer Preview

> Historical notes for the published source-only prerelease.

Cumea turns self-hosted agent runtimes into a small team you can message from desktop or mobile.
Agents keep a durable identity and thread, can hand work to one another, surface decisions in one
Needs-you inbox, and run on a computer or VM controlled by the user.

## Highlights

- Agent-first desktop and Expo companion instead of an endless list of disposable chats.
- Claude, Codex, Grok, Gemini, and Box-backed adapters behind one event contract.
- Durable work records, handoffs, attachments, routines, approvals, and task artifacts.
- Optional connected apps and local/cloud computer use with explicit consent boundaries.
- Self-hosted mobile pairing with hashed host-side device tokens and a least-privilege remote API.
- Customizable animated blob avatars with useful working/waiting/success/error states.
- No Cumea telemetry, managed VM, or hosted credential proxy.

## Preview boundaries

This is not a production-support release. macOS arm64 was the first intended desktop binary target,
but no binary should be treated as normally installable until Developer ID signing, notarization,
Gatekeeper assessment, and clean-user launch checks are complete. Linux and Windows were
portable-source/package previews without hands-on validation. The mobile app had
typecheck/JavaScript-export coverage only; it was not an App Store or Play Store build and carried
no physical-device support claim.

Laptop-off execution requires Cumea to keep running on an authenticated host or VM owned by the
user. Cumea does not supply a managed cloud computer. Remote access must sit behind user-controlled
HTTPS or a private tunnel; the raw HTTP listener is not an internet-facing server.
