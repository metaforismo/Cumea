# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers and technically confident operators evaluating whether they can run useful AI agents without handing the runtime, credentials, or task history to a Cumea-operated cloud.

## Product Purpose

Cumea is an open-source, self-hosted workspace where each conversation is a real AI agent. A desktop or user-owned VM is the host for providers, tools, routines, and durable history; the paired mobile app is a control surface for that same host.

## Positioning

Cumea makes a visible council of role-based agents available across desktop and mobile while the models, credentials, and execution host remain under the user's control.

## Operating Context

Visitors evaluate Cumea from the landing page, inspect the source and developer-preview release on GitHub, then build it from source. Real work happens through provider CLIs and optional tools configured on a user-controlled host. The mobile companion pairs to that host for agent lists, chat, approvals, stop controls, and routine status.

## Capabilities and Constraints

- MIT licensed and source available.
- v0.1.0 is a source-only developer preview; there is no signed or notarized macOS download.
- Cumea does not provide a managed VM and does not run providers on the phone.
- Provider and tool capabilities vary by runtime and remain explicitly documented.
- Demo content on the landing page is illustrative and must not imply a real provider task ran.
- The landing is an isolated static Vite app with no runtime service dependency.

## Brand Commitments

Use the Cumea name, the existing Cumea icon, and Mote-based bot avatars. The product voice is direct, technically honest, restrained, and independent; competing products are references, not identities to copy.

## Evidence on Hand

- Interactive desktop and mobile previews in `index.html` and `src/main.js`.
- Real product screenshots already imported by the landing build: hero, computer panel, approval card, model picker, and marketplace.
- Product truth and current capability matrix in the repository root `README.md`.
- Mote geometry and semantic activity states already implemented in the desktop, mobile, and landing codebases with MIT attribution.
- No customer logos, testimonials, adoption metrics, signed download, or production benchmarks are available and none may be fabricated.

## Product Principles

- Prove control and continuity with real product behavior, not abstract claims.
- Keep every release, platform, and capability claim bounded by current evidence.
- Make role-based agents immediately understandable without fantasy naming.
- Treat mobile as a paired control surface, not a second runtime.
- Prefer one clear action and an inspectable source trail over conversion theater.

## Accessibility & Inclusion

The landing must support keyboard navigation, visible focus, semantic controls, reduced motion, adequate contrast, and layouts without horizontal overflow at 1440, 390, and 320 pixel widths.
